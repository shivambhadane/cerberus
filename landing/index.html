01 // The problem ↘

Everything is critical, so nothing is.

A security team can act on a handful of issues a week. Most tooling hands them thousands, sorted by the wrong thing entirely.

01

Unknown exposure

Cloud servers get spun up and forgotten. Test environments stay online. Shadow IT lives outside every inventory. You cannot defend what you do not know exists.

02

Alert overload

Scanners report volume, not priority. One scan returns thousands of findings, and a generic severity score will not tell you which one to start with on Monday.

03

Severity is not danger

A 9.8 may never be touched by a real attacker. A 6.5 may be under mass exploitation by ransomware crews today. Static scores miss what is happening in the wild.

03 // How it works ↘

Five stages, each independently replaceable.

Every stage takes typed input and produces typed output, so any one can be swapped — the scoring engine can become a learned model without touching discovery.

01 / DISCOVER

Find what you expose

Certificate transparency logs, DNS resolution, an async TCP connect scan, and technology fingerprinting from HTTP headers and service banners. Pure Python — no external scanner needed.

02 / INGEST

Normalize and deduplicate

Findings collapse into one asset model, so a weekly scan refreshes what it already knows rather than cloning it. Assets are tagged by business criticality from naming conventions and exposed services.

03 / ENRICH

Ask what attackers are doing

The CISA KEV catalogue and EPSS scores are cached globally — identical for every tenant, so they are fetched once rather than per scan — then each fingerprint is resolved to CVEs through the NVD CPE dictionary.

04 / SCORE

Rank by exploitability

Active exploitation, predicted exploitation, asset criticality, and exposure blend into a single score. CVSS is deliberately not a top-level weight.

05 / DELIVER

Hand over a short list

A ranked list through the REST API, the cerberus report CLI, or the dashboard — each one showing why a finding sits where it does.

04 // Explainability ↘

A number you can argue with.

A score nobody can interrogate is a score nobody will act on. Every finding ships with the reasoning that produced it, verbatim from the scoring engine.

risk_score: 83.4
reasoning: Actively exploited (CISA KEV, added 2023-10-10); 100% predicted exploitation probability (EPSS); high-criticality asset (hostname indicates a production or data-tier system); internet-facing web service on port 443.

06 // Rules of engagement ↘

Scan only what is yours.

Authorized use only

Cerberus performs active reconnaissance — port scanning and vulnerability detection — alongside passive OSINT. Running it against systems you neither own nor have written permission to test may violate computer misuse law regardless of intent.

Every scan requires an explicit authorization attestation, in the CLI and the dashboard alike. Cerberus reports what could be exploited; it ships no weaponized exploit code and will not exploit anything itself.
