Three problems that compound

Security teams can act on a handful of issues a week. Most tooling hands them thousands, sorted by the wrong thing.

01

Unknown exposure

Cloud servers get spun up and forgotten. Test environments stay online. Shadow IT lives outside every inventory. You cannot defend what you do not know exists.

02

Alert overload

Scanners report volume, not priority. A single scan returns thousands of findings, and a generic severity score does not tell you which one to start with on Monday.

03

Severity is not danger

A 9.8 may never be touched by a real attacker. A 6.5 may be under mass exploitation by ransomware crews today. Static scores miss what is happening in the wild.

Five stages, each independently replaceable

Every stage takes typed input and produces typed output, so any one of them can be swapped — the scoring engine can become a learned model without touching discovery.

01

Discovery

Certificate transparency logs, DNS resolution, an async TCP connect scan, and technology fingerprinting from HTTP headers and service banners. Pure Python — no external scanner required.

02

Ingestion

Normalizes findings into one asset model and deduplicates on re-scan, so a weekly scan refreshes what it sees rather than cloning it. Assets are tagged by business criticality from naming conventions and exposed services.

03

Enrichment

Caches the CISA KEV catalogue and EPSS scores globally — the same for every tenant, so it is fetched once, not per scan — then resolves each fingerprint to CVEs through the NVD CPE dictionary.

04

Exploitability scoring

Blends active exploitation, predicted exploitation, asset criticality, and exposure into one score. CVSS is deliberately not a top-level weight.

05

Delivery

A ranked list through the REST API, the cerberus report CLI, or the dashboard — each showing why a finding sits where it does.

A number you can argue with

A score nobody can interrogate is a score nobody will act on. Every finding ships with the reasoning that produced it — verbatim, from the scoring engine.

risk_score: 83.4
reasoning: Actively exploited (CISA KEV, added 2023-10-10); 100% predicted exploitation probability (EPSS); high-criticality asset (hostname indicates a production or data-tier system); internet-facing web service on port 443.

Scan only what is yours

Authorized use only

Cerberus performs active reconnaissance — port scanning and vulnerability detection — alongside passive OSINT. Running it against systems you neither own nor have written permission to test may violate computer misuse law regardless of intent.

Every scan requires an explicit authorization attestation, in the CLI and in the dashboard alike. Cerberus reports what could be exploited; it contains no weaponized exploit code and will not exploit anything itself.
